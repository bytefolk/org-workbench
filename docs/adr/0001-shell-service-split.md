# ADR-0001: 壳-服务分离（Electron 壳 + 本地控制面服务）

状态：已决（D0 落地）｜ 日期：2026-08-23

## 决策

org-workbench 采用壳-服务分离：Electron 壳（apps/desktop）与本地控制面服务（apps/server，仅 127.0.0.1）是两个进程；壳在启动时以子进程拉起服务，服务亦可独立运行。

## 理由

- web/移动端扩展支点：未来 web/移动端直连同一控制面与同一契约包，是"换壳复用"，不是重写。
- 职责清晰：文件系统监听、引擎消费、组织状态机全部收敛在服务侧；壳只负责窗口、对话框、IPC 桥与渲染。
- 失败隔离：壳崩溃不影响服务状态；服务探活失败时壳给出可执行的下一步（"失败也有路"）。

## 借鉴边界（clean-room）

形态参考 t3code（壳-服务分离/本地服务+权限模式）与 hermes-desktop（本地后端+视图组织），仅借交互与进程形态，零代码复制（见 ADR-0004）。

## 后果

- 进程间需 ready 协议（stdout 行，含端口与 boot-token）与探活；已实现并有测试。
- 打包需同时分发壳与服务；D0 以开发模式验证，打包细节随 macOS 构建里程碑落地。
